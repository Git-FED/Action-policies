Static site test strategy

Short version: The site is tested as a collection of real files. Every route must exist, local links must resolve, and deployment output must preserve the same structure as the source.

Structural checks

Every HTML page needs a doctype, language attribute, title, primary heading, and shared footer. Internal links and local assets are checked against the actual directory routes so a beautiful page cannot hide a missing destination.

Deployment checks

The build creates a clean dist/ directory from site/. Both GitHub Pages and Cloudflare Pages consume that same output. Redirect stubs include a real HTML fallback and a canonical destination, which keeps legacy links understandable even when server-side redirect behavior is unavailable.

Manual review

Before a release, open the home page, documentation index, a policy page, a redirect, support, donate, and each legal page. Test keyboard navigation, a narrow viewport, reduced-motion preferences, the age confirmation behavior, and the browser console. Payment processors are not tested with real transactions in CI.
